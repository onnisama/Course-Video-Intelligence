# 工程实现规范

按改动范围阅读对应章节。具体技术选型和目录边界以现有实现及团队确认的方案为准，项目拟议结构见[仓库目录约定](project-implementation.md#仓库目录约定)。全仓工作流和审批要求见[AGENTS.md](../AGENTS.md)。

## 前端

采用 Vue 3，沿用仓库现有的 Vue、Vite、TypeScript 和 UI 组件库版本。

- 页面组件负责展示和交互，API 请求集中管理，复用已有客户端逻辑。
- 对加载中、空状态、失败和无权限提供清晰反馈。
- 前端路由守卫和按钮显示用于交互，课程资源与业务操作的权限由服务端校验。第三方 ASR 和 LLM 请求由后端发起，服务密钥仅从服务端的受控配置读取。

## 后端

采用 Python 与 FastAPI，路由层负责 HTTP 输入输出及依赖注入，业务规则放在可测试的服务层。

- 使用明确的数据模型校验请求和响应，统一处理异常、超时和外部服务错误。响应中的错误信息应避免暴露密钥或内部堆栈。
- 在服务端校验重要业务操作的权限。视频处理、AI 调用等耗时任务按已批准的架构使用后台任务或队列。
- 沿用已批准的架构，新增微服务、复杂消息中间件或 Kubernetes 须有明确需求并经团队评审。

## API 契约

- 实现前明确路径、方法、请求、响应、错误码和权限。采用 OpenAPI 时先改契约，再同步后端实现、前端类型、调用方和测试。
- 前后端字段沿用同一契约。破坏性变更需要检查所有调用方与测试，并记录原因。
- 验证正常响应、参数错误、权限拒绝和异常路径。

## ASR、LLM 与媒体处理

### 第三方服务

- 通过后端服务或 Provider Adapter 封装 ASR 和 LLM，避免业务代码耦合服务商。配置请求超时、有限重试和可诊断的失败状态。
- 记录服务商、模型、任务状态、耗时和必要的错误信息，日志按要求脱敏。
- 使用 JSON Schema、Pydantic 或同等方式校验 LLM 输出。对校验失败提供可诊断错误，或按流程重试、转人工处理。
- 字幕、章节和摘要须支持人工检查与修订。用固定 Mock 响应验证成功、超时、限流、无效结构和失败重试。

### 字幕与时间戳

- 字幕片段至少包含文本、开始时间和结束时间，字段和单位以已确认的契约为准。校验时间戳非负、开始早于结束，且结束时间不超过视频时长。
- 保留原始 ASR 输出与人工修订之间的可追溯关系，搜索跳转使用服务端保存的时间戳。
- 覆盖空字幕、时间段重叠、时间越界、识别失败和无效模型输出。

### 文件与任务

- 校验上传文件大小、格式和实际媒体类型。服务端生成安全的存储文件名，拒绝客户端指定的文件路径。
- 记录任务状态、错误原因和重试策略，按约定清理临时音频和中间文件。
- 使用合成、公开授权或明确获准的媒体作开发与测试素材。真实课程媒体入库或用作 Fixture 前须确认授权。

## 数据库与数据隔离

- 改动表、索引、约束或关系前检查已有设计和数据依赖。结构变更使用可审查的迁移脚本或版本化 SQL，并验证迁移、约束与关键查询。
- 大体积视频原则上存放于文件存储，数据库保存元数据与文件引用，具体方案以经评审的设计为准。
- 查询用户、课程、视频、字幕和笔记时校验访问权限和数据隔离。
- 数据库集成测试使用隔离的测试库或 Schema，测试禁止清理或修改共享数据。共享开发库和演示库的破坏性迁移须经审查及授权。

## 集成与验收测试

- 逐步覆盖核心业务流程。请从教师、助教、学生等真实用户角色的角度定义验收场景。
- 设计条目关联需求，测试用例关联需求与设计，确保代码和文档反映实际系统。
