# AI 课程视频结构化管理与智能检索平台

## 项目简介

高校课程录播和教学视频包含大量课堂知识，但视频通常以连续音视频形式呈现。学生复习时，可能需要反复拖动进度条寻找某个知识点；教师和助教也可能需要花费时间整理字幕、章节和课程内容。

这是同济大学《软件工程课程设计》项目，拟建设一个面向高校课程场景的课程视频结构化管理与智能检索平台。系统通过视频管理、语音识别、自然语言处理和文本检索，将课程视频转化为可检索、可定位、可维护的学习资源。

以上痛点和功能目前属于项目初始假设，最终需求以真实干系人访谈、调研证据和教师审核结果为准。

### 项目目标

1. 为教师提供课程、视频和处理任务的统一管理能力。
2. 将课程视频中的语音内容转换为带时间戳的字幕。
3. 辅助生成课程章节、章节摘要等结构化内容，并支持人工审核和修订。
4. 支持学生按关键词检索课程内容，并定位到视频中的对应时间点。
5. 建立清晰的角色权限、处理状态、异常反馈和数据管理机制。
6. 通过可运行的 Web 系统验证业务流程，并形成符合课程要求的工程文档与过程记录。

### 目标用户

| 用户角色 | 主要目标 | 典型操作 |
|---|---|---|
| 教师 | 管理课程和教学视频，审核 AI 生成内容 | 创建课程、上传视频、查看处理状态、审核字幕与章节 |
| 助教 | 协助维护课程资源 | 校对字幕、修订章节、协助整理课程内容 |
| 学生 | 高效观看和复习课程视频 | 浏览课程、观看视频、搜索知识点、跳转到对应时间 |
| 平台管理员（按需纳入） | 维护平台运行与账号权限 | 管理用户、角色和平台配置 |

## 核心业务流程

1. 教师创建课程并上传课程视频。
2. 系统保存视频及元数据，创建视频处理任务。
3. 后端提取音频，并调用第三方语音识别服务生成带时间戳的字幕。
4. 系统将字幕内容提交给大语言模型，生成候选章节和摘要。
5. 教师或具有相应权限的助教审核、修订并确认结构化内容。
6. 学生进入已授权课程，观看视频、检索字幕，并跳转到对应时间点。

### 课程设计交付范围

课程设计拟分三个增量交付“课程管理—视频上传—字幕生成—章节审核—内容检索—时间戳跳转”的核心流程。各增量的范围见[计划交付增量](docs/project-implementation.md#计划交付增量)。

暂不将以下内容列为课程设计必做范围：

- 在线直播、实时课堂和复杂教务管理；
- 自研语音识别或大语言模型；
- 完整的考试、成绩和作业管理系统；
- 原生移动端应用；
- 复杂知识图谱、全量课件 OCR 和多模态问答；
- 面向大规模商业用户的高可用与多地域部署。

新增功能应先评估课程价值、用户证据、实现成本和对核心闭环的影响，再决定是否纳入迭代。

## 技术方案

以下为初始建议，具体选型以团队确认后的方案为准。

### 初始技术栈

| 层次 | 建议技术 | 主要用途 |
|---|---|---|
| 前端 | Vue 3、Vite、TypeScript | Web 页面与交互 |
| UI 组件 | Element Plus | 表单、表格、上传、弹窗等管理界面 |
| 路由与状态 | Vue Router、Pinia | 页面路由和共享状态 |
| 后端 | Python、FastAPI | 业务接口、权限控制、任务编排和 AI 服务接入 |
| 数据校验 | Pydantic | API 请求与响应校验 |
| 数据访问 | SQLAlchemy、Alembic | ORM 和数据库迁移 |
| 关系数据库 | PostgreSQL | 用户、课程、视频元数据、字幕、章节、任务等结构化数据 |
| 媒体处理 | FFmpeg | 视频信息读取和音频提取 |
| AI 服务 | 第三方 ASR API、LLM API | 字幕识别、章节与摘要生成 |
| 视频播放 | HTML5 Video | 视频播放与时间戳定位 |
| 文件存储 | 开发阶段本地文件目录 | 保存视频、音频及处理产物 |
| 容器与部署 | Docker、Docker Compose | 统一开发和部署环境 |
| 测试 | Pytest、Vitest | 后端和前端测试 |
| 协作与 CI | GitHub Issues、Pull Requests、GitHub Actions | 任务跟踪、代码评审和自动化测试 |

### 系统架构

系统拟采用前后端分离的 Web 架构。

- **前端层**负责课程管理、视频播放、字幕展示、内容检索和审核交互。
- **后端业务层**负责身份与权限校验、课程和视频业务、处理任务管理、检索接口。
- **媒体处理层**调用 FFmpeg 提取音频，协调 ASR 与 LLM 处理流程。
- **数据层**保存用户、课程、视频元数据、字幕片段、章节、任务状态和审计信息。
- **外部服务层**通过服务适配器调用第三方 ASR 和 LLM API。

视频文件与关系型数据库中的业务元数据分开管理。数据库保存文件标识、存储位置、大小、格式和处理状态等信息，不默认将大体积视频二进制内容直接存入关系数据库。

## 本地运行

以下命令在仓库根目录执行。首次运行需安装依赖，之后可直接启动。

### 环境要求

| 工具 | 版本 | 说明 |
|---|---|---|
| Python | 3.13 | 后端运行时 |
| Node.js | 24 | 前端构建与开发服务器 |
| pnpm | 11.1.1 | 前端包管理器，版本由 `frontend/package.json` 的 `packageManager` 字段固定 |
| Docker Compose | 支持 `up --wait` | 启动本地 PostgreSQL |

### 启动本地 PostgreSQL

启动 Docker 后，首次使用时将根目录的 `.env.example` 复制为 `.env`，填写自己的本地开发密码 `POSTGRES_PASSWORD`。默认端口为 `5432`。如果端口已被占用，修改 `.env` 中的 `POSTGRES_PORT`。

```bash
docker compose up -d --wait db
docker compose ps db
docker compose exec db psql -h 127.0.0.1 -U course_video -d course_video -W -tAc 'SELECT 1'
```

容器状态应为 `healthy`。最后一条命令使用示例中的用户名和库名，输入本地密码后应输出 `1`。本机客户端使用 `127.0.0.1` 和 `.env` 中的 `POSTGRES_PORT` 连接。

执行 `docker compose down` 可停止开发数据库，数据保存在 `postgres_data` 命名卷中。用户名、库名和密码在数据卷首次初始化时生效。

### 启动后端

```bash
cd backend
python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1
# macOS / Linux
source .venv/bin/activate

python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

验证健康检查：

```bash
curl http://127.0.0.1:8000/api/health
# {"status":"ok"}
```

运行后端测试：

```bash
cd backend
python -m pytest
```

### 检查后端数据库连接并执行迁移

启动 PostgreSQL 并安装后端依赖后，在 `backend/` 目录执行以下命令。后端和 Alembic 都读取仓库根目录的 `.env`，进程环境变量优先。`POSTGRES_HOST` 默认为 `127.0.0.1`。如果本地密码含 `$`、`#` 或空格，在 `.env` 中用单引号包住该值。

```bash
python -m app.database
python -m alembic upgrade head
python -m alembic current
```

连接检查应输出 `1`，迁移状态应显示 `0001 (head)`。`0001` 建立 Alembic 版本基线，业务表由后续功能的迁移创建。运行数据库集成检查时使用单独的本地或 CI 测试库。

### 启动前端

另开一个终端：

```bash
cd frontend
pnpm install
pnpm run dev
```

浏览器访问 <http://127.0.0.1:5173>。页面经 Vite 开发代理请求 `/api/health` 并显示后端连接状态；后端未启动时页面显示连接失败，可点击「重新检查」重试。若端口 5173 已被占用，Vite 会报错退出，释放端口后再启动。

其他前端命令：

```bash
pnpm run typecheck   # TypeScript 类型检查
pnpm run build       # 类型检查 + 生产构建，产物在 frontend/dist/
```

### 持续集成

`.github/workflows/ci.yml` 在 push 和 Pull Request 时运行后端测试、数据库连接与迁移检查、前端类型检查与构建。后端任务使用专用的临时 PostgreSQL 服务，校验连接、执行迁移并检查所有最新版本均已应用。
